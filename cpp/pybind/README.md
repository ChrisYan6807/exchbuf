# exchbuf pybind11 bindings

Per-protocol Python extension modules generated from the `.eb` files under
`solutions/*/source_gen/`. Each `<basename>_pybind.cpp` is auto-generated by
`dsl/gen_pybind.py`; don't edit by hand.

## Build

```sh
cd pybind
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

Output is `build/*_pb.cpython-*.so` — one shared object per protocol.
Add `pybind/build/` to `PYTHONPATH` (or copy the `.so` files into your
package) to import them.

## Python API

For each message `Msg` in `<basename>.eb` you get a class `<basename>_pb.Msg`
with:

| API                     | What it does                                            |
| ----------------------- | ------------------------------------------------------- |
| `Msg.allocate(cap=4096)`| zero-fill a `cap`-byte buffer; `cap` ≥ `fixed_size()`   |
| `Msg.from_bytes(b)`     | copy `b` into a buffer of exactly `len(b)` bytes        |
| `Msg.fixed_size()`      | header size (static)                                    |
| `Msg.wire_size(b)`      | parses `b` to compute total on-wire length              |
| `m.size()`              | current wire length of this instance                    |
| `m.capacity()`          | underlying buffer size                                  |
| `bytes(m)`              | wire-format bytes of length `m.size()`                  |
| `m.<field>`             | scalar / enum / string / FloatDecimal property          |
| `m.<var_array>`         | indexed view (`m.grp[0].key = ...`); requires counter set first |
| `m.<var_str>`           | read/write `bytes`; setter auto-updates the size field  |

### Build-from-scratch idiom (Scope A+ with `allocate`)

```python
import sandbox1_pb as eb

m = eb.NewOrder.allocate(300)    # 300-byte buffer
m.qty   = 100
m.sz    = 2                      # set the counter FIRST
m.grp[0].key   = 9
m.grp[0].value = "abc"           # FixedLengthString accepts str
m.grp[1].key   = 10
m.grp[1].value = "xyz"
out = bytes(m)                   # exactly fixed_size() + 2*sizeof(RptGrp)
```

### Parse-then-mutate idiom

```python
m = eb.NewOrder.from_bytes(wire_bytes)
print(m.qty, m.sz)
for rpt in m.grp:                # iterable
    print(rpt.key, bytes(rpt))
m.qty = 250
out = bytes(m)
```

### Enums

```python
print(eb.MsgType.New)            # MsgType(New)
m.msgType = eb.MsgType.Cancel    # assignment via py::cast'd enum value
print(m.msgType == eb.MsgType.Cancel)
```

## Known limits in this first cut

- Inheriting messages re-bind only their **own** fields; the parent's fields
  are still reachable through the C++ struct but not exposed as properties
  on the child Holder. Plan: emit pass-through properties for inherited
  fields too.
- `optional_by_enum` / `optional_by_len` / `optional_by_bit` /
  `optional_by_value` members are exposed **read-only** for now (Python
  receives the underlying `OptionalByEnumRef` etc. as an opaque object).
  Writing through them requires the binding to know the specific type
  variant — a follow-up.
- `FloatingRef<T>`-emitted fixed-after-var members are bound generically
  via `OptionalRef` semantics; the read path works for `to_int()`/`raw_value()`
  on the contained primitive, but typed accessors per variant aren't generated.
- Cross-file types (e.g. `MsgHeader` from Millennium used in LSE) require
  loading both modules in Python (`import Millennium_pb` before
  `import LSE_pb`) because pybind11 cross-module casting needs the parent
  module's bindings to be registered first.

## Regen

`dsl/gen_pybind.py <file.eb>` prints the binding `.cpp` to stdout. To
re-generate all of them in place:

```sh
for eb in solutions/*/source_gen/*/*.eb solutions/*/source_gen/*/*/*.eb; do
    base=$(basename "$eb" .eb)
    dsl/gen_pybind.py "$eb" > "pybind/${base}_pybind.cpp"
done
```
